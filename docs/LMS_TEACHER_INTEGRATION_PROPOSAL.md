# 학생 성과 관리 ↔ LMS 연동 제안서

## 확정 사항 (2025년 1월)

다음 세 가지로 **구현 방향이 확정**되었습니다.

1. **방안 A(완전 통합)**  
   학생 성과 관리 기능은 별도 강사 전용 페이지 없이 **과정별 LMS 한 곳**에서만 제공한다.

2. **진입 경로**  
   **「나의 강의」 목록에서 곧바로 해당 과정 LMS로 이동**한다.  
   수강생 분석·출석·평가·설문을 위한 **별도 과정 선택 단계는 두지 않는다.**

3. **LMS 탭 구성**  
   LMS에 **수강생 전용 탭**을 둔다. 경로: **`/lms/students`** (과정별로 `/admin/courses/:id/lms/students`).

---

## 1. 현재 상황 정리

### 1.1 강사 대시보드 – 학생 성과 관리 하위 메뉴

| 메뉴             | 경로                  | 동작                                   |
|------------------|-----------------------|----------------------------------------|
| 수강생 분석      | `/teacher/students`   | 과정 선택 후 수강생 목록(enrollments)  |
| 출석 관리        | `/teacher/attendance` | 별도 전용 뷰                           |
| 평가 및 채점     | `/teacher/exams`      | 과정 선택 후 시험 목록(exams API)      |
| 설문 및 역량진단 | `/teacher/surveys`    | 설문 목록(surveys API)                 |

- **특징**: 메뉴 진입 시 과정을 선택하지 않고, **각 페이지 안에서** 과정을 선택하는 구조이며, **강사 전용 뷰**(teacher_*)로 구현되어 있음.

### 1.2 관리자 LMS (과정별)

| 탭       | 경로                         | 용도           |
|----------|------------------------------|----------------|
| 대시보드 | `/admin/courses/:id/lms`     | 과정 요약, 출석률, 진도 등 |
| 출결관리 | `.../lms/attendance`          | 일자별 출결    |
| 훈련일지 | `.../lms/training-logs`       | 훈련 일지      |
| 과제관리 | `.../lms/assignments`         | 과제           |
| CBT/시험 | `.../lms/cbt`                 | 시험 출제·관리 |
| 성적관리 | `.../lms/grades`              | 성적           |
| 상담일지 | `.../lms/counseling`          | 상담           |
| NCS평가  | `.../lms/ncs-eval`            | NCS            |
| 설문/평가 | `.../lms/surveys`            | 설문           |
| 취업관리 | `.../lms/employment`         | 취업           |

- **특징**: **과정별 URL**(`/admin/courses/:id/lms/...`)을 사용하며, `lms_header`에서 역할(role)에 따라 로고·뒤로가기만 강사용으로 바꿔 줌. **탭·라우트는 관리자 경로와 동일.**

### 1.3 중복되는 기능

- **수강생** → enrollments API (강사 수강생 분석, LMS 여러 탭에서 공통 사용)
- **출석** → 강사 출석 관리 vs LMS 출결·QR 출석
- **평가·채점** → 강사 평가/채점 vs LMS CBT·성적
- **설문** → 강사 설문 vs LMS 설문/평가

**결론**: 동일한 데이터와 기능을 **강사 전용 페이지**와 **과정별 LMS** 두 갈래로 나누어 제공하는 구조임.

---

## 2. LMS 연동·통합이 필요한 이유

### 2.1 과정 단위 업무

수강생 조회, 출석, 평가, 설문은 모두 **특정 과정에 속한 업무**이므로,  
「과정을 먼저 정한 뒤, 그 과정의 LMS에서 처리」하는 흐름이 자연스럽습니다.

### 2.2 PRD·HRD 관점

LMS PRD에서는 「학생학사관리」와 「강사학사관리」를 **하나의 학사(LMS)** 로 묶어 정의하고 있으며,  
출결, 성적, 훈련일지, 상담 등도 **과정별**로 관리하는 것이 HRD 관행에 맞습니다.

### 2.3 중복 제거

강사 전용 뷰와 관리자 LMS를 계속 분리하면  
동일 기능을 두 번 구현·유지보수하게 되고,  
「수강생은 여기서? 출석은 저기서?」와 같은 이용자 혼란이 생깁니다.

### 2.4 기존 구조와의 정합성

API(enrollments, exams, surveys, attendance 등)는 이미 **course_id(과정 ID)** 기준으로 동작하고,  
LMS도 **과정별 라우트**로 설계되어 있어, 「과정 선택 → LMS」로 통합하는 것이 구조와 잘 맞습니다.

**따라서** 학생 성과 관리 하위 메뉴(수강생 분석, 출석, 평가/채점, 설문/역량진단)는 **LMS와 연동·통합하는 것이 타당**합니다.

### 2.5 「통합 관리」의 의미

- **관리자가 쓰는 LMS**와 **강사가 쓰는 LMS**가 **같은 화면·같은 탭·같은 라우트**를 사용하고,
- **권한(관리자 / 강사)**에 따라 「보이는 메뉴」와 「가능한 동작」만 다르게 두는 것을 의미합니다.
- 데이터와 「어디서 무엇을 하는가」는 하나로 모으고, **역할에 따른 제한**만 두는 것이 「통합 관리」입니다.

## 3. 확정된 구현 방향

### 3.1 방안 A: 완전 통합

- **학생 성과 관리** 관련 기능은 **과정별 LMS 한 곳**에서만 제공합니다.
- 강사 전용 페이지(`/teacher/students`, `/teacher/attendance`, `/teacher/exams`, `/teacher/surveys`)는  
  **과정 선택 전용 허브**로 두거나, 단계적으로 **제거·리다이렉트**로 정리합니다.
- **실제 업무(수강생 조회, 출석, 평가, 설문)**는 **과정별 LMS** 내 탭에서만 수행합니다.

### 3.2 진입 경로: 「나의 강의」에서 곧바로 해당 과정 LMS로

- **별도의 과정 선택 단계를 두지 않습니다.**
- 강사는 **「나의 강의」**(`/teacher/courses`) 목록에서 **해당 과정의 「강의실 입장」** 등을 클릭하면  
  **곧바로 그 과정의 LMS**(예: `/admin/courses/:id/lms`)로 이동합니다.
- 「수강생 분석」「출석 관리」「평가 및 채점」「설문 및 역량진단」 메뉴를 클릭했을 때도  
  **과정 선택 페이지를 거치지 않고**,  
  **「나의 강의」 목록으로 이동**한 뒤, 원하는 과정의 LMS로 들어가도록 연결할 수 있습니다.  
  (또는 해당 메뉴 클릭 시 「나의 강의」와 동일한 과정 목록을 보여 주고, 과정 클릭 시 해당 LMS로 직행.)

**정리**:  
- **기본 진입**: 나의 강의 → (과정 클릭/강의실 입장) → **해당 과정 LMS**.  
- **학생 성과 관련 메뉴**: 나의 강의(또는 동일 과정 목록) → 과정 선택 → **해당 과정 LMS** (및 필요 시 해당 탭으로 이동).

### 3.3 LMS 수강생 전용 탭: `/lms/students`

- LMS에 **수강생 전용 탭**을 신규 추가합니다.
- **경로**: `/admin/courses/:id/lms/students` (과정별).
- **역할**:
  - 과정별 **수강생 목록** 조회·검색·필터(수강중, 수료, 중도탈락 등).
  - PRD의 「수강생 통합 관리」에 대응하는 **과정별 수강생 정보·상태**를 한곳에서 관리.
- **대시보드**와의 관계:  
  대시보드에는 요약 정보만 두고, **상세 목록·관리는 수강생 탭**에서 수행하도록 구분하는 것을 권장합니다.

### 3.4 강사 메뉴 ↔ LMS 탭 매핑 (확정)

| 강사 메뉴(기존)   | LMS 탭        | 경로 예시                          | 비고 |
|------------------|---------------|------------------------------------|------|
| 수강생 분석      | **수강생**    | `.../lms/students`                | 신규 탭 |
| 출석 관리        | 출결관리      | `.../lms/attendance`               | 기존 탭 |
| 평가 및 채점     | CBT/시험·성적관리 | `.../lms/cbt`, `.../lms/grades` | 기존 탭 |
| 설문 및 역량진단 | 설문/평가     | `.../lms/surveys`                  | 기존 탭 |

- 훈련일지, 상담일지, NCS, 취업 등은 PRD상 강사 역할에도 포함될 수 있으므로,  
  당장은 관리자 위주라도 **강사에게 동일 LMS 탭을 노출**하고,  
  필요 시 이후 단계에서 「강사는 조회만」 등 **동작 제한**을 두는 방식을 권장합니다.

## 4. 공통 적용 사항

### 4.1 라우트 (관리자·강사 공용)

- **과정별 LMS**는 관리자·강사가 **동일한 경로**를 사용합니다.  
  예: `/admin/courses/:id/lms`, `/admin/courses/:id/lms/students`, `.../lms/attendance` 등.
- **진입만 구분**:
  - **관리자**: `/admin/courses`(과정 목록) → 과정 선택 → 해당 과정 LMS.
  - **강사**: `/teacher/courses`(나의 강의) → 해당 과정 「강의실 입장」 등 → **동일 LMS 경로**.
- `lms_header` 등에서 **역할이 강사일 때** 로고·뒤로가기 링크를 `/teacher`, `/teacher/courses`로 설정하는 방식은 유지합니다.

### 4.2 강사 권한

- LMS 내 **특정 탭·기능**을 「관리자 전용」으로 두고 싶다면,  
  같은 라우트를 쓰되 **역할(admin/teacher)**에 따라 **탭 노출·버튼·API 호출**만 제한합니다.
- 「강사는 조회만, 관리자는 수정까지」와 같은 **세밀한 권한**은  
  API 및 프론트에서 **role·permission** 기준으로 처리합니다.

### 4.3 「나의 강의」 → LMS 진입

- **`/teacher/courses`**(나의 강의 관리)에서 **「강의실 입장」** 클릭 시  
  **해당 과정 LMS**(예: `/admin/courses/:id/lms`)로 **곧바로** 이동하는 현재 동작을 **기본 진입 방식**으로 유지합니다.
- 「수강생 분석」「출석 관리」「평가 및 채점」「설문 및 역량진단」은  
  **나의 강의 목록(또는 동일 과정 목록)에서 과정 선택 후 해당 과정 LMS(및 해당 탭)** 로 연결되도록 구현합니다.

### 4.4 API

- 기존 **enrollments, exams, surveys, attendance** 등 **API는 그대로** 사용합니다.
- **뷰·라우팅·메뉴 연결**만 통합하면 되며, 데이터 구조 변경은 필요하지 않습니다.

## 5. 구현 순서 제안

1. **1단계: LMS 수강생 탭 추가**
   - `/admin/courses/:id/lms/students` 라우트 및 **수강생 전용 뷰** 추가.
   - 과정별 수강생 목록·검색·필터(상태 등) 구현.
   - `lms_header` 탭 메뉴에 **「수강생」** 항목 추가.

2. **2단계: 강사 사이드바·진입 경로 정리**
   - **「나의 강의」**를 **유일한 과정 진입점**으로 유지.
   - 「수강생 분석」「출석 관리」「평가 및 채점」「설문 및 역량진단」 클릭 시  
     **나의 강의(또는 동일 과정 목록)** → **과정 선택** → **해당 과정 LMS**(및 해당 탭)로 이동하도록 연결.
   - 필요 시 `/teacher/students` 등 기존 경로는 **나의 강의 또는 과정 선택 페이지로 리다이렉트**하도록 변경.

3. **3단계: 강사 전용 페이지 정리**
   - `/teacher/students`, `/teacher/attendance`, `/teacher/exams`, `/teacher/surveys`의 **실제 기능**을  
     단계적으로 **LMS 쪽으로 이전**하거나,  
     해당 경로는 **과정 선택 후 LMS 해당 탭으로 리다이렉트**만 수행하도록 정리.
   - 중복 뷰 제거 후 **deprecated** 처리 또는 삭제.

4. **4단계: 권한·UX 점검**
   - 강사로 로그인 시 LMS 탭·버튼 노출이 의도대로인지 확인.
   - 「나의 강의」에서 곧바로 해당 과정 LMS로 넘어가는 흐름이 자연스러운지 검증.

---

## 6. 정리

- **학생 성과 관리**와 **LMS**는 **같은 데이터·같은 화면(과정별 LMS)**을 사용하도록 **완전 통합**합니다.
- **진입**은 **「나의 강의」 목록에서 해당 과정을 선택하면 곧바로 그 과정의 LMS**로 이동하는 방식입니다.
- LMS에는 **수강생 전용 탭**(`/lms/students`)을 두어, 과정별 수강생 조회·관리를 한곳에서 수행합니다.
- 관리자와 강사가 **동일한 과정별 LMS**를 사용하고, **역할에 따라 노출·동작만** 다르게 하여 **통합된 학사 관리**가 이루어지도록 합니다.

본 문서의 확정 사항(방안 A, 나의 강의 직행 진입, 수강생 전용 탭)을 기준으로 단계별 구현을 진행하면 됩니다.
