# 회차 상태 표시 통일 제안 (관리자 수동 변경 우선)

## 현상
- **종합대시보드**: `course_sessions.status`(DB 값)만 사용 → 관리자가 "진행중"/"마감"으로 바꾸면 날짜가 지나도 그대로 표시됨.
- **통합교육과정 리스트**: API에서 `applyEffectiveStatus`로 **날짜 기반** 상태로 덮어씀 → 날짜가 지나면 "종료"로 표시되어 불일치.

## 원칙
**관리자가 수동으로 변경한 회차 상태는 교육과정관리·종합대시보드 등 관련 모든 화면에서 동일하게 표시되어야 한다.**

## 제안: 표시는 DB 상태 단일 소스로 통일

### 1. 단일 소스: DB의 `course_sessions.status`
- 관리자가 "진행중" / "마감" 등으로 **직접 변경**한 값은 이미 DB에 저장되어 있음.
- **날짜 기준 자동 반영**은 "상태 일괄 동기화" 버튼(`POST /api/course-sessions/sync-status`) 실행 시에만 DB를 갱신하면 됨.

### 2. 적용 위치
| 위치 | 현재 | 변경 후 |
|------|------|--------|
| 종합대시보드 (과정 현황) | DB `status` 사용 | **유지** (변경 없음) |
| 통합교육과정 리스트 API | `applyEffectiveStatusToList` 적용 | **제거** → DB `status` 그대로 반환 |
| 회차 단건 조회 (관리/편집용) | `getEffectiveSessionStatus` 적용 | **제거** → DB `status` 그대로 반환 |
| 상태 일괄 동기화 (`sync-status`) | 날짜 기준으로 DB UPDATE | **유지** (날짜 반영은 여기서만) |

### 3. 수강생/공개용 API
- 수강생 내 수강 목록(`/me/enrollments`), 공개 과정 목록 등은 **필요 시** 기존처럼 날짜 기반 유효 상태를 쓸 수 있음 (선택 사항).
- 본 제안은 "관리자·교육과정 관련 페이지 통일"에 초점을 둠.

### 4. 결과
- 관리자가 수동으로 "진행중" 또는 "마감"으로 변경 → **모든 리스트(교육과정관리, 종합대시보드 등)에 동일하게 표시**.
- "날짜 기준으로 상태 반영"이 필요할 때만 관리자가 **상태 일괄 동기화**를 실행하면 됨.
