# 교육과정관리 메인 vs 일반과정등록 페이지 분리 제안

## 1. 현재 상황

| 구분 | URL | 내용 | 비고 |
|------|-----|------|------|
| 교육과정관리 메인 | `/admin/courses` | 등록된 과정/일반과정 탭 + 통합 검색 + 과정 테이블 | 사이드바 "교육과정관리" 클릭 시 |
| 일반과정등록 | `/admin/courses` | **동일** | 사이드바 "일반과정등록" 클릭 시 **같은 페이지** |
| 승인받은 과정 | `/admin/courses/approved` | NCS 승인 과정 리스트·등록 | 별도 페이지 |
| 회차별 과정개설 | `/admin/courses/sessions` | 회차별 개설 리스트·등록 | 별도 페이지 |

**문제**: "교육과정관리 메인"과 "일반과정등록"이 같은 URL·같은 화면이라, 메인은 요약/진입점 역할을 하지 못하고, 등록 전용 화면도 구분되지 않음.

---

## 2. 제안 개요

- **교육과정관리 메인** (`/admin/courses`): **대시보드형 메인 페이지**  
  → 승인 과정 리스트 섹션 + 회차별 개설 리스트 섹션을 한 화면에 배치.
- **일반과정등록** (`/admin/courses/register`): **별도 전용 페이지**  
  → 현재 `/admin/courses`의 "등록된 과정/일반과정" 탭·검색·테이블·신규 등록 기능을 이 경로로 이동.

---

## 3. URL 및 역할 정리

| 구분 | URL | 역할 |
|------|-----|------|
| **교육과정관리 메인** | `GET /admin/courses` | 과정관리 진입점. 승인 과정·회차별 개설 **요약 리스트** + 각 "전체보기" 링크 |
| **일반과정등록** | `GET /admin/courses/register` | 등록된 과정/일반과정 탭, 검색, 테이블, 신규 등록, 엑셀 등 **(현재 메인과 동일 기능)** |
| 승인받은 과정 | `GET /admin/courses/approved` | 승인 과정 전체 리스트·상세·등록 (기존 유지) |
| 회차별 과정개설 | `GET /admin/courses/sessions` | 회차별 개설 전체 리스트·상세·등록 (기존 유지) |
| 과정분류관리 / 회차별복사 등 | 기존 URL 유지 | 변경 없음 |

---

## 4. 교육과정관리 메인 페이지 구성 제안

**레이아웃**: 한 페이지 안에 **두 개의 섹션**을 세로로 배치.

### 4.1 상단 헤더

- 제목: "교육과정 관리"
- 브레드크럼: 홈 > 과정관리 > 교육과정 관리
- (선택) 간단 통계: 승인 과정 N건, 회차 개설 N건

### 4.2 섹션 1: 승인받은 과정 리스트

- **제목**: "승인받은 과정" (아이콘 + "전체보기" 링크 → `/admin/courses/approved`)
- **내용**:  
  - 승인 과정 API로 **최근 N건**(예: 5~10건) 또는 **요약 테이블** 표시  
  - 컬럼 예: 과정명, NCS/비NCS, 등록일, [상세] 버튼  
- **CTA**: "전체보기" → `/admin/courses/approved`, "승인 과정 등록" → `/admin/courses/approved/register` (기존 링크 유지)

### 4.3 섹션 2: 회차별 과정 개설 리스트

- **제목**: "회차별 과정 개설" (아이콘 + "전체보기" 링크 → `/admin/courses/sessions`)
- **내용**:  
  - 회차 개설 API로 **최근 N건** 또는 **요약 테이블** 표시  
  - 컬럼 예: 과정명, 회차, 훈련기간, 상태, [상세/수업계획서] 버튼  
- **CTA**: "전체보기" → `/admin/courses/sessions`, "회차 개설 등록" → `/admin/courses/sessions/register` (기존 링크 유지)

### 4.4 (선택) 퀵 링크

- "일반과정 등록하기" → `/admin/courses/register`
- "과정분류관리" → `/admin/courses/categories`
- "회차별 과정복사" → `/admin/courses/copy`

---

## 5. 일반과정등록 페이지 (별도 페이지)

- **URL**: `GET /admin/courses/register`
- **내용**: **현재 `admin_courses.ts`의 전체 UI/로직을 이 경로로 이동**
  - 리스트 구분: "등록된 과정" / "일반과정" 탭
  - 통합 과정 검색 (훈련년도, 회차, 과정 구분, 상태, 키워드)
  - 과정 테이블 (체크박스, No, 구분/회차, 과정명, 기간/시간, 정원/현원, 담당교사, 수강료, 상태, 관리)
  - 페이지네이션, 엑셀 저장, 선택 삭제
  - "과정 신규 등록" → 기존처럼 승인 과정 불러오기 / 직접 입력 모달
  - "회차별 관리" 링크 → `/admin/courses/sessions`
- **사이드바**: "일반과정등록" 클릭 시 `activeMenu = 'courses-register'`, 현재 메인과 동일한 서브 메뉴 구조 유지 가능.

---

## 6. 사이드바 변경 제안

| 메뉴 | 변경 전 | 변경 후 |
|------|---------|---------|
| 교육과정관리 (메인) | `/admin/courses` | `/admin/courses` **(새 메인: 섹션 2개)** |
| 일반과정등록 | `/admin/courses` | `/admin/courses/register` **(별도 페이지)** |
| 과정분류관리 | `/admin/courses/categories` | 유지 |
| 승인받은 과정 | `/admin/courses/approved` | 유지 |
| 회차별 과정개설 | `/admin/courses/sessions` | 유지 |
| 회차별 과정복사 | `/admin/courses/copy` | 유지 |

- "교육과정관리" 클릭 시: `activeMenu = 'courses'` → 새 메인(대시보드) 표시.
- "일반과정등록" 클릭 시: `activeMenu = 'courses-register'` → `/admin/courses/register` 표시.

---

## 7. 구현 시 고려사항

1. **라우팅**
   - `GET /admin/courses` → **새 메인 뷰** (승인 리스트 섹션 + 회차별 리스트 섹션).
   - `GET /admin/courses/register` → **기존 `admin_courses.ts` 내용** (뷰/로직 이동 또는 재사용).

2. **API 재사용**
   - 승인 과정: 기존 승인 과정 목록 API (페이지/limit 파라미터로 최근 N건).
   - 회차별 개설: 기존 회차별 개설 목록 API (동일하게 최근 N건).

3. **기존 링크**
   - 다른 화면에서 "교육과정 관리"로 돌아가는 링크가 `/admin/courses`라면, 새 메인이 보이므로 수정 불필요.
   - "일반과정 등록/리스트"로 직접 가는 링크는 `/admin/courses/register`로 변경 필요 여부만 점검.

4. **진입 경로 정리**
   - 관리자 첫 진입: "교육과정관리" → 메인(요약 2개 섹션).
   - 등록/수정 작업: "일반과정등록" 또는 메인의 "일반과정 등록하기" → `/admin/courses/register`.

---

## 8. 요약

| 항목 | 제안 |
|------|------|
| **교육과정관리 메인** | `/admin/courses`를 **페이지 섹션으로 나누어** "승인받은 과정 리스트" + "회차별 과정 개설 리스트"를 한 화면에 표시. 각 섹션에서 "전체보기"로 기존 상세 페이지 이동. |
| **일반과정등록** | **별도 페이지** `/admin/courses/register`로 분리. 현재 메인에 있던 등록/검색/테이블/신규 등록 기능을 이 페이지에서만 제공. |
| **사이드바** | 메인 = `/admin/courses`, 일반과정등록 = `/admin/courses/register`로 링크 분리. |

이렇게 하면 "메인 = 요약·진입점", "일반과정등록 = 등록·리스트 전용"으로 역할이 명확해집니다.
