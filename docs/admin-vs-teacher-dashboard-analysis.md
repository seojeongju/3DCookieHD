# 관리자 대시보드 에러 원인 분석 및 대책

## 질문
> "강사 대시보드를 수정했는데 관리자 대시보드에서 왜 에러가 많이 발생하는가?"

---

## 1. 구조 정리: 관리자 vs 강사는 **완전히 다른 컴포넌트**

| 구분 | 관리자 (Admin) | 강사 (Teacher) |
|------|----------------|----------------|
| **진입 경로** | `/admin` | `/teacher` |
| **대시보드 뷰** | `src/views/admin.ts` | `src/views/teacher_dashboard.ts` |
| **사이드바** | `hrd_sidebar.ts` → `hrdSidebar('dashboard')` | `teacher_sidebar.ts` → `teacherSidebar('dashboard')` |
| **공유 여부** | hrd_sidebar는 **관리자 전용** | teacher_sidebar는 **강사 전용** |

- **관리자**: `admin.ts`가 `hrdSidebar('dashboard')`를 주입. 모든 `/admin/*` 페이지가 `hrd_sidebar` 사용.
- **강사**: `teacher_dashboard.ts`가 `teacherSidebar('dashboard')`를 주입. `teacher_sidebar`는 `lms_menu_config`만 참조.

즉, **강사용 코드만 수정했다면 관리자 쪽 소스는 직접 건드리지 않은 상태**입니다.

---

## 2. 그런데도 관리자에서 에러가 나는 이유 (가능한 원인)

### 2-1. **실제로는 관리자용 사이드바를 수정했을 가능성**
- 화면이 비슷해 보여서 **강사 사이드바**라고 생각하고 **`hrd_sidebar.ts`**를 수정했을 수 있습니다.
- `hrd_sidebar`는 **관리자 전용**이므로, 여기를 바꾸면 **모든 관리자 페이지**에 영향이 갑니다.
- (이전 대화에서 로그아웃/사용자명 표시 수정이 `hrd_sidebar.ts`에서 이뤄졌고, 그게 관리자 대시보드에 반영되는 구조입니다.)

### 2-2. **관리자 대시보드 자체의 구조적 취약점 (가장 유력)**
관리자 쪽은 **한 번도 손댄 적이 없어도** 아래 구조 때문에 에러가 나기 쉽습니다.

- **`admin.ts`**
  - 하나의 **큰 템플릿 리터럴** 안에 HTML + **인라인 스크립트**가 모두 들어 있음.
  - 그 안에 `${hrdSidebar('dashboard')}`로 **hrd_sidebar 전체(HTML + 스크립트)**가 문자열로 끼워 넣어짐.
- **결과**
  - 최종 HTML이 **admin 본문 스크립트 + hrd_sidebar 스크립트**가 한 문서에 이어붙여진 형태.
  - 인라인 스크립트 안에 `const`/`let`, 화살표 함수, 템플릿 리터럴, 정규식 등이 그대로 나가면:
    - 구형 브라우저/특정 환경에서 **SyntaxError** (예: `Unexpected token 'if'`, `Unexpected string`) 발생 가능.
    - 문자열/정규식 이스케이프가 템플릿 리터럴 안에서 한 번 더 해석되면서 **의도와 다르게 출력**될 수 있음.

즉, **“강사를 수정해서 관리자가 깨진다”기보다는, 관리자 쪽이 원래 인라인 스크립트 구조 때문에 에러가 나기 쉬운 상태**라고 보는 것이 맞습니다.

### 2-3. **공유 리소스 (가능성은 낮음)**
- 두 대시보드 모두 Tailwind CDN, Chart.js, Font Awesome 등 **동일한 외부 스크립트**를 사용.
- 페이지가 **다른 URL**(`/admin` vs `/teacher`)이므로, **같은 탭에서 동시에 로드되지는 않음**.
- 따라서 “강사 페이지 스크립트가 관리자 페이지를 망가뜨린다” 같은 **직접적인 간섭** 가능성은 낮습니다.

---

## 3. 대책 제안

### 3-1. **수정 시 “어디를 고치는지” 명확히 하기**
- **관리자 전용**: `admin.ts`, `hrd_sidebar.ts`, 기타 `admin_*.ts` 뷰.
- **강사 전용**: `teacher_dashboard.ts`, `teacher_sidebar.ts`, `teacher_*.ts`, `lms_menu_config.ts`(강사/메뉴용).
- 강사만 수정할 때는 **`hrd_sidebar.ts`를 건드리지 않도록** 하면, 관리자 레이아웃/스크립트는 영향받지 않습니다.

### 3-2. **관리자 인라인 스크립트 의존도 줄이기 (근본 대책)**
- **현재**: `admin.ts` + `hrd_sidebar` 안에 긴 인라인 스크립트가 그대로 HTML에 포함됨.
- **권장**:
  - 관리자 전용 **별도 JS 파일** (예: `admin-dashboard.js`)을 두고,
  - `admin.ts`에서는 `<script src="/static/admin-dashboard.js"></script>` 형태로만 로드.
  - 그러면:
    - 템플릿 리터럴/이스케이프 문제가 사라지고,
    - 브라우저가 스크립트를 **일반 JS 파일**로 파싱해 SyntaxError 가능성이 줄어듦.
- **단기**: 인라인 스크립트를 유지할 경우, 이미 적용한 것처럼 **ES5 스타일(`var`, `function`)으로 통일**하고, 문자열/정규식은 **클라이언트에 나갈 형태**를 정확히 계산해 이스케이프하는 방식이 안전합니다.

### 3-3. **관리자 전용 스크립트만 테스트하기**
- 강사 수정 후 **반드시 `/admin`을 직접 열어** 확인.
- 브라우저 개발자 도구 콘솔에서 **SyntaxError / 전역 에러**가 없는지 확인.
- 이렇게 하면 “강사만 수정했는데 관리자에서 터진다”를 **원인(실제로 hrd_sidebar 수정 여부, 인라인 스크립트 이슈)**과 구분할 수 있습니다.

### 3-4. **사이드바 수정 시 역할 구분하기**
- **관리자 로그인/사이드바/권한**: `hrd_sidebar.ts`만 수정.
- **강사 로그인/사이드바/메뉴**: `teacher_sidebar.ts`, `lms_menu_config.ts`만 수정.
- 한 컴포넌트를 “공용”으로 쓰지 않고, **역할별로 파일을 나누어 둔 현재 구조를 유지**하는 것이 안전합니다.

---

## 4. 요약

| 항목 | 내용 |
|------|------|
| **원인** | 강사만 수정했다면 **직접 원인은 아님**. 관리자 에러는 (1) **실제로는 hrd_sidebar를 수정했거나**, (2) **관리자 대시보드의 큰 인라인 스크립트 구조** 때문에 발생했을 가능성이 큼. |
| **대책** | (1) 수정 대상 파일이 관리자용(`hrd_sidebar`, `admin.ts`)인지 강사용(`teacher_sidebar`, `teacher_dashboard`)인지 구분, (2) 관리자 스크립트는 가능하면 **별도 JS 파일로 분리**, (3) `/admin` 직접 열어서 콘솔 에러 확인. |

이 문서는 `docs/admin-vs-teacher-dashboard-analysis.md`로 저장되어 있으며, 필요 시 팀 내 공유용으로 사용하시면 됩니다.
