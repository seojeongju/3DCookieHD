# 로그인 세션 로직 제안

## 현재 구조 요약

| 항목 | 내용 |
|------|------|
| 인증 방식 | JWT (Bearer), `localStorage`에 저장 |
| 토큰 만료 | **24시간** (`src/utils/jwt.ts`의 `exp: now + 24*60*60`) |
| 로그아웃 | 클라이언트만: `localStorage.removeItem('token')` |
| 서버 세션 | 없음 (무상태 JWT만 사용) |

즉, 로그아웃을 누르지 않으면 **최대 24시간** 동안은 토큰이 유효하고, 서버는 토큰을 “끊는” 방법이 없습니다.

---

## 제안 옵션 (난이도·효과 순)

### 1) 토큰 유효 시간 단축 (가장 단순)

**내용:** JWT 만료 시간을 24시간 → 1~2시간 등으로 줄인다.

- **장점:** 구현이 쉬움. 만료 후 API가 401을 주면, 이미 만든 `redirectToLogin` 흐름으로 로그인 페이지로 보낼 수 있음.
- **단점:** 1~2시간마다 재로그인해야 할 수 있어 사용성이 떨어질 수 있음.
- **구현:** `src/utils/jwt.ts`에서 `exp: now + (24 * 60 * 60)` 값을 원하는 초 단위로 변경 (예: 1시간 = `60 * 60`).

**적합:** “일정 시간 지나면 무조건 끊기게”만 하고 싶을 때.

---

### 2) 클라이언트 유휴(Idle) 타임아웃 (추천)

**내용:** 마지막 활동(클릭·API 호출 등) 이후 N분이 지나면 클라이언트에서 토큰을 지우고 로그인 페이지로 보냄.

- **장점:**  
  - “자리 비운 채로 두면” 자동으로 세션 종료.  
  - 서버 변경 없이, 공통 스크립트 하나만 넣으면 됨.
- **단점:**  
  - 탭을 여러 개 열면 탭마다 타이머가 따로 돌아, 한 탭에서 로그아웃돼도 다른 탭은 그대로일 수 있음.  
  - 토큰 자체 만료(1번)와 같이 쓰는 것을 권장.
- **구현:**  
  - `activity` 이벤트(클릭, 키 입력, fetch 등)마다 “마지막 활동 시각” 갱신.  
  - setInterval로 주기적으로 “현재 시각 − 마지막 활동 > N분”이면 `localStorage` 제거 후 `/login?redirect=...` 이동.  
  - 이 로직을 공통 레이아웃/헤더가 로드하는 하나의 `session.js`(또는 기존 헤더 스크립트)에 두고, 로그인 필요 페이지에서만 로드.

**적합:** “사용하지 않는 동안만 세션 끊기” + 보안과 사용성 균형.

---

### 3) Access Token 단축 + Refresh Token (선택)

**내용:**  
- **Access Token:** 짧은 만료(예: 15분~1시간).  
- **Refresh Token:** 긴 만료(예: 7일~30일), DB 또는 KV에 저장.  
- Access 만료 시 클라이언트가 `/api/auth/refresh`로 Refresh Token을 보내 새 Access Token 발급.  
- Refresh 만료/무효면 재로그인.

- **장점:**  
  - 자주 쓰는 사용자는 재로그인 없이 오래 쓸 수 있고,  
  - Access Token이 짧아져서 탈취 시 피해 범위를 줄일 수 있음.
- **단점:**  
  - Refresh Token 저장소(DB/KV) 설계·구현 필요.  
  - 로그아웃 시 해당 Refresh Token 무효화 로직 필요.  
  - 클라이언트에서 401 시 refresh 후 재시도 로직 필요.

**적합:** 보안 요구가 높고, “한 번 로그인하면 며칠은 끊기지 않게”도 원할 때.

---

### 4) 서버 측 세션 저장 (로그아웃 시 완전 무효화)

**내용:**  
- 로그인 시 세션 ID를 D1/KV 등에 저장.  
- API에서 JWT 검증 후, “이 사용자·이 토큰(또는 세션 ID)이 아직 유효한지” DB/KV를 한 번 더 조회.  
- 로그아웃 시 해당 세션을 삭제하거나 무효화.

- **장점:**  
  - “지금 이 기기에서 로그아웃” = 서버에서도 즉시 끊김.  
  - 관리자 권한으로 특정 사용자 세션 강제 종료 가능.
- **단점:**  
  - 매 요청마다 DB/KV 조회 필요.  
  - 구조 변경이 큼.

**적합:** “로그아웃 = 서버에서도 세션 완전히 끊기”가 필수일 때.

---

## 추천 조합

- **당장 적용하기 좋은 조합:**  
  **1) JWT 만료 1~2시간** + **2) 클라이언트 유휴 타임아웃(예: 30분)**  
  - 서버: `jwt.ts`의 `exp`만 조정.  
  - 클라이언트: 공통 `session.js`에서 “N분 동안 활동 없으면 로그아웃 처리 + 로그인 페이지 리다이렉트”.

- **이후 단계(필요 시):**  
  - “재로그인 빈도를 줄이고 싶다” → **3) Refresh Token** 도입 검토.  
  - “로그아웃 시 서버에서 완전히 끊고 싶다” → **4) 서버 세션 저장** 검토.

원하시는 방향(예: “2번만”, “1+2”, “3번까지”)을 정해주시면 그에 맞춰 구현 단계별로 구체 코드까지 작성해 드리겠습니다.
